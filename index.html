Summary

The research question has not changed: to what extent does adding a verifier agent to a role-aware RAG assistant reduce wrong answers and leaks of restricted information, and what does it cost? The prototype runs Version A (role filter only) and Version B (role filter + verifier) on the same questions.

Since v0.9 the prototype was tested by hand, a dozen bugs and design gaps were fixed, real university documents replaced the mock-only data, and every change was measured on question sets written before the change. The web page was rebuilt so that people outside the project can understand what happened to each answer.

31real public policy documents from 11 universities, mostly Dubai campuses
270labelled questions in 6 sets (45 in v0.9)

Architecture

Three agents run in order behind a small API. The key design idea, from the tutor's feedback, is that the verifier never trusts the tags stored in the search index: it checks permissions against its own access register and the original documents.

PartFileWhat it does
Loginsrc/auth.pyIssues a signed token (HMAC-SHA256, 8 hours) that carries the role. The role is never read from the question or the request body.
Ingestionsrc/ingest.pySplits documents into chunks of 2 paragraphs, tags each chunk with its allowed roles and its university, embeds and stores it.
Retrieversrc/agents/retriever.pySearches only chunks the role may see (filter inside the vector query), optionally only one university's documents. Top 4, ties broken by chunk id so results repeat exactly.
Answerersrc/agents/answerer.pyOffline: copies the best-matching sentences. OpenAI mode: GPT-4o-mini, temperature 0, cites every sentence.
Verifiersrc/agents/verifier.py, relevance.pyChecks the draft (next section) and passes, rewrites once, or blocks.
Orchestratorsrc/orchestrator.pyRuns the agents; Version A skips the verifier. Removing a leaked source does not use up the one quality rewrite.
APIapi.pyFastAPI: login, ask, datasets, document upload/preview, health, demo re-index.
Web pageapp.pyStreamlit page: choose a university, ask, compare A and B side by side, see why the checker approved or blocked, upload a document and see its chunks and vectors.
Real documentssrc/fetch_real.pyDownloads the public documents listed in data/real/manifest.csv, extracts the text, checks SHA-256 hashes. Texts are not committed (copyright).
Evaluationeval/run_eval.py, stats.pyRuns every question set through A and B under four tagging conditions; reports 95% Wilson intervals and exact McNemar tests.
One-command startrun_demo.pyDownloads, indexes, starts the API and page, opens the browser.

Two modes: offline (default, no API key: hashing embeddings, extractive answerer, rule-based verifier) and openai (text-embedding-3-small and gpt-4o-mini). All results so far are offline.

One question, step by step

A student asks "What is the late penalty per day at the American University in Dubai?" with "All universities" selected.

  1. Login. The page holds a token that says student. Saying "I'm a lecturer" in the question changes nothing.
  2. Search. The retriever asks ChromaDB only for chunks tagged visible to students. It returns the 4 closest chunks; here they come from the Canadian University Dubai handbook, because AUD's documents do not mention late penalties.
  3. Draft. The answerer writes an answer from those chunks and cites them.
  4. Version A shows that draft: an answer about another university, presented as if it were AUD's rule.
  5. Version B runs the checks. The question names AUD, the source is from Canadian University Dubai, so the source is dropped, the answerer tries again with what is left, nothing relevant remains, and the safe reply is shown. The page explains: "You asked about American University in Dubai, but the draft came from a Canadian University Dubai document."

What we can say in the paper

  • Leaks: across every set and condition, Version B never added a leak and stopped every leak it had an independent signal for. The only B leak is an unlabelled document when the register is wrong too, which is the design's stated limit.
  • Wrong university: the university check is the most effective rule we tested: 14 of 15 and 7 of 8 traps refused, against 1 for Version A.
  • Cost: rules written for our own mock documents gave false alarms on real ones ("confidential", then "marking guide" in Curtin's manual), which is why B's over-refusal reached 23% on the dubai set.
  • Accuracy is limited by the offline answerer and by very long handbooks, not by the verifier. Run 10 is kept in the repo but is invalid (the new documents were missing from the register; fixed before run 11).

Try it yourself

Python 3.11 or 3.12 and Git; no API key. The full guide, including Windows commands and a 10-minute test list, is at the top of the README.

git clone https://github.com/ma3str0o0/role-aware-rag-assistant.git
cd role-aware-rag-assistant
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python run_demo.py

The first start downloads 31 public documents (about a minute) and opens http://localhost:8501. Please send Nikita anything wrong or confusing, with a screenshot.
